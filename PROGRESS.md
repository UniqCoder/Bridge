## 1. What the prototype is, honestly

A **frontend-only prototype** running in *fixture mode*. All detection logic runs in TypeScript in the browser over data generated by `web/scripts/build-fixtures.mjs`, which reads the real XChainWatcher CSVs and the reference engine's artifacts, and **fails the build if any asserted number drifts**. There is **no backend yet**: no API, no live stream, no database, no chain connection from the UI. The Python reference engine (`D:\OM\bridgewitness`, 55 tests passing) exists separately and produced the evidence bundles and live-demo artifact the UI displays.

## 4. Features in the prototype

**Pages (14).** Landing `/` · Monitor · **USP demos** · **Attack tests** · Evidence · Incidents (+ `inc_nomad`, `inc_live`) · **What-if** · Nomad replay · **Flow map** (three.js) · **Live bridge** (3D + alert takeover) · **Results** · Evidence spec · Architecture · 404. (Bold: renamed in plain words; URLs unchanged: `/console/gauntlet`, `/theatre`, `/graph`, `/witness`, `/eval`.)

**Working features.**
- Feed picker: simulated replay, Nomad, Ronin; virtual clock 1–300×, seek, event-density scrubber with attack markers.
- Three signal panels (pairs, volume, signers), alert queue with risk breakdown, exploit type and reasons, incident grouping, transaction stream with explorer links.
- Evidence library (12 bundles), collapsible bundle tree with violating fields marked, in-browser verification, tamper mode with diff.
- Cross-chain flow graph: 575 releases as edges between Moonbeam message commitments and Ethereum beneficiaries by token; a "no deposit" node; fan-out ranking (message id 4922 → 279 releases).
- Counterfactual lanes with log latency slider (0 s → 6 days), Nomad/Ronin toggle.
- Ledger playground on the landing: edit a release and watch the real rule respond.
- Eval page: model card, engine latency, the three signals measured on the datasets.
- Accessibility basics: reduced-motion, focus rings, aria-live twin on Witness; verdicts never colour-only.

**Not working / disabled.** Launching attacks on real chains (demo mode runs them in the browser), guardian holds on-chain, the S0/S2–S7 scenario picker, live SSE, baselines/ablation tables (pending), testnet.

## 6. Synthetic or preview inventory (what a judge should be told)

1. **Simulated attack replay** — fully synthetic (seeded). Background amounts and deposit→release delays are resampled from real Ronin transfers; attacks and controls are scheduled by us; the 9-validator set and signatures are fabricated.
2. **Signer behaviour on any dataset** — only on the simulated feed and the live local chains; Nomad/Ronin data has no signers.
3. **Nomad/Ronin verdicts** — computed by our TS port of the rule over the real CSV rows ("engine preview"), not by the Python engine. Same rule, golden-tested on 12 bundles, but not yet the backend's output.
4. **Watermarks, observer lag, overdue SLA, incident window, copycat thresholds** — placeholder constants in `web/src/data/replay.ts` and `monitor.ts`.
5. **Live bridge results** — come from one reference run (local Ganache chains, unaudited demo contracts, 0 public-chain transactions).
6. **Evidence bundles for Nomad/Ronin** — none; the datasets have no receipts or proofs. All 12 bundles are from the reference engine's local simulation.
7. **Eval baselines, ablation, S0–S7** — not computed; displayed as pending.
8. **USP demos** — the simulated bridge in `/console/lab` (proof demo: 6 invented deposits and an invented chain; watermark demo: 10 invented releases; gate demo: invented routes and a 6× fast window) and the 12 attacks in `/console/gauntlet` (invented amounts and addresses; reorg, early-release and overdue timing are a thin engine layer on top of the rule). The checking rule, the Merkle-Patricia mechanics and the SHA-256/verification code in them are real.

## 7. Planned (not built)

Backend Steps 1–5 (`HANDOFF.md`): Nomad reconciliation replay in Python and clean-room matcher; state-proof evidence and optimistic gate with `holdWithEvidence`; incident engine, SSE stream, overdue lifecycle; fault injector, evaluation and baselines, counterfactual in Python; Gauntlet launch, guardian endpoints, golden export. Then swap fixtures for the live API endpoint by endpoint. Roadmap: public-testnet adapter, light-client finality, production-bridge adapters (Nomad/Ronin formats, then Wormhole/Axelar), Witness Bundles as an open standard. Detectors must be ported to Python alongside Step 3.

## 8. Known limits

Finality is an RPC assumption · headers supplied by our server · absence proof works only for bridges that store deposits in state (otherwise watermark mode) · supports lock/mint and burn/release routes, not liquidity or intent bridges · single-writer engine (one worker) · first JS chunk ≈ 660 KB.
